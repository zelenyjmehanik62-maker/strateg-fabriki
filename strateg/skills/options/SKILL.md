# Навык: варианты

Шаг 4. Дать руководителю настоящий выбор. Три версии одной идеи — это не выбор. Варианты должны отличаться тем, на что делается ставка, и у каждого должен быть сильный противник.

## Когда применять

После картины ситуации. Повторно — когда пересмотр отменил основание выбранного варианта.

## Что читаешь и что пишешь

Читаешь: `brief.md`, `findings.md`, реестр.
Пишешь: `options.md`; новые гипотезы и прогнозы — командой `claim`.

## Шаги

1. **Начни с двух обязательных вариантов.** Они задают планку для остальных:
   - **Оставить как есть.** Что произойдёт, если ничего не менять, — с прогнозом, а не «всё останется как было». Это точка отсчёта: любой другой вариант должен быть лучше неё, иначе он не нужен.
   - **Закрыть направление.** Что высвободится (деньги, люди, внимание), что будет потеряно, насколько это обратимо. Вариант рассматривай всерьёз, даже если пользователь его не хочет.
2. **Добавь варианты с разной ставкой** — не меньше одного, обычно два-три. Рычаги: другая аудитория, другая задача пользователя, другое предложение или цена, другой канал, другая модель дохода, партнёрство. Проверка на различие: если два варианта выбирает один и тот же ответ на решающий вопрос — это один вариант в двух размерах, объедини их.
3. **Для каждого варианта распиши** по виду ниже. Самое важное — три пункта:
   - **Что должно быть правдой.** Допущения, без которых вариант не работает. Каждое — в реестр как `hypothesis`, со ссылкой на факты, на которые оно опирается.
   - **Польза, затраты, доходы.** Порядок величин, а не точность. Цифры будущего — `forecast` с названными допущениями. Считай скриптом и сохрани расчёт.
   - **Сильные возражения.** Не меньше двух на вариант.
4. **Возражения пиши от лица умного противника.** Представь человека, который знает продукт не хуже руководителя и считает вариант ошибкой: что он скажет? Слабое возражение («это потребует усилий») не считается. На каждое дай ответ со ссылкой — или честно напиши, что ответа нет. Возражение без ответа — не недостаток документа, а самая ценная его часть.
5. **Сведи в таблицу сравнения** по одним и тем же критериям: на чём стоит, главный риск, цена ошибки, обратимость, что проверить первым и за сколько.
6. **Дай рекомендацию и её условия.** Какой вариант ты выбрал бы и почему — и что должно выясниться, чтобы ты рекомендовал другой. Рекомендация не обязана быть самым смелым вариантом.
7. **Сверь критичные факты.** `python3 tools/strateg.py vet <проект>` покажет факты, на которых стоят варианты и которые ещё не сверены по смыслу. Передай карточки помощнику `fact-checker` (или сверь сам, см. `AGENTS.md`) и запиши вердикты. Вердикт `no` или `partial` — исправь вариант до того, как показывать его человеку: варианты, стоящие на неподтверждённом, не показывают.
8. **Передай выбор человеку.** Покажи таблицу и рекомендацию, спроси, какой вариант он выбирает. Не продолжай без ответа: `step <проект> --waiting "выбор варианта"`.
9. **После выбора:** `step <проект> --done options --next "стратегии для варианта <буква>"` и запиши решение по навыку `follow`, процедура А.

## Вид результата — `options.md`

Заголовки вариантов — строго «## Вариант <буква>. <название>»: по ним работает проверка.

```markdown
# Варианты

## Вариант A. Оставить как есть
**Суть.** …
**На чём основан.** Факты со ссылками [E-…].
**Что должно быть правдой.** Гипотезы, названные гипотезами [E-…].
**Польза, затраты, доходы.** По оценке … [E-…].
**Риски.** …
**Возражения.**
1. <сильное возражение> — ответ: … [E-…] / ответа нет.
2. …
**Что проверить первым.** Самая дешёвая проверка главного допущения.
**Обратимость.** Легко ли отступить.

## Вариант B. <название>
…

## Вариант C. Закрыть направление
…

## Сравнение
| | A | B | C |
|---|---|---|---|
| Ставка | | | |
| Главный риск | | | |
| Цена ошибки | | | |
| Обратимость | | | |
| Первая проверка | | | |

## Рекомендация
Какой вариант и почему (вывод). Что должно выясниться, чтобы рекомендация изменилась.
```

## Чего не делать

- Не ставь рядом с любимым вариантом два заведомо слабых. Если вариант нельзя защитить всерьёз, его не должно быть в списке.
- Не различай варианты размером («скидка 10%», «скидка 20%», «скидка 30%»).
- Не прячь прогнозы под видом фактов: будущее всегда `forecast`, и в тексте это видно.
- Не выбирай за человека и не начинай стратегию до его ответа.

## Проверка результата

- Не меньше трёх вариантов, есть «оставить как есть» и «закрыть направление».
- У каждого варианта не меньше двух возражений, и хотя бы одно из них неприятное.
- По таблице сравнения видно, чем варианты отличаются по существу.
- `check` проходит.
