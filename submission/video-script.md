# T12. Сценарий демонстрационного видео

Первая версия — Ника-Codex, 16 ноября 2026. Переписан под живое демо Ратмиром-Claude (за Нику) 17 ноября: конкретная задача и три новых кадра — подделка ловится проверкой, несогласие руководителя, поправка к постановке после перерыва.

Хронометраж: **9 минут 20 секунд**, резерв до предела в 10 минут — 40 секунд.

Статус: сценарий для согласования; видео ещё не записано. Как проводится сам прогон под запись — `docs/DEMO.md`. С 18 ноября запись ведёт Ника в Codex на Windows.

## Что должно стать понятно жюри

Руководитель приносит размытый вопрос. Агент уточняет постановку, сам собирает открытые данные и у каждого факта хранит точную цитату. Он показывает разные варианты с возражениями и не сдаётся без оснований, когда с ним спорят. Выбор остаётся за человеком. Потом из выбранного варианта агент делает две согласованные стратегии и план проверки. В новом чате работа продолжается из файлов, а поправка руководителя меняет только то, что она затрагивает.

## Задача демо

Подписка «Семейная безопасность» для пожилых у **условного** оператора связи: защита от мошеннических звонков, местоположение, кнопка SOS. Только открытые данные, полный режим. Это **собственная задача команды**: бриф МегаФона не был опубликован. На первом кадре так и написать.

## Как записываем

Две записи экрана без звука: основной прогон и продолжение в новом чате. Озвучка и подписи добавляются при монтаже. Ожидание модели ускоряется с пометкой «×8» в углу кадра; на подписи у каждой сцены — настоящее время по журналу сеанса.

## Команды для подтверждающих кадров

Выполнять из `strateg/` после прогона. Номера `E-…` выбрать из настоящего реестра демо и вписать в `recording-plan.md`.

```bash
python3 tools/strateg.py status demo
python3 tools/strateg.py show demo E-<номер>
python3 tools/strateg.py check demo
python3 tools/strateg.py usage <журнал сеанса>.jsonl --project demo
```

Кадр с подделкой — последовательность команд из `submission/evidence/check.txt`, во временной папке; запускается `python3 submission/build_pdf.py --evidence` или вручную.

## Как честно сократить полтора часа до девяти минут

- Исходные записи сохраняем целиком. Ожидание модели ускоряем с пометкой, повторное чтение файлов вырезаем; у каждой сцены — настоящее время по журналу.
- Не склеиваем вопрос из одного прогона с ответом из другого и не выдаём заранее подготовленный файл за только что созданный.
- Продолжение в новом чате — настоящим новым окном, а не внутри прежнего разговора.
- Кадр с подделкой снят отдельно и подписан как проверка механизма на учебном проекте.
- Если инструмент упал — оставляем короткий кадр ошибки и того, что было дальше.

## Чего нельзя говорить

- «Мы быстрее и дешевле обычного чата». Замер показал обратное по времени и расходу (`bench/comparison.md`).
- «86% выводов верны». Измерена доля строк с цифрами, у которых есть ссылка, а не истинность.
- «Это демо по брифу МегаФона» или «данные МегаФона». Это собственная задача на открытых данных, оператор — условный.
- «Проверка ловит любую ошибку». Скрипт ловит выдуманные цитаты и цифры, сверщик — расхождение смысла; ошибки возможны.
- «Модельные интервью подтвердили спрос». Они дают только гипотезы.
- «Расходов нет». На подписке это не счёт, а оценка по прайс-листу.
