# Проверка соответствия и метрики качества

Дата: 16.11.2026. Официальные критерии в `docs/CASE.md`: проработанность, масштаб использования нейротехнологий, имплементация, качество (по 10 баллов, экспертное оценивание). Далее - **предложенная внутренняя приёмка**, а не новая шкала конкурса и не измеренные результаты будущего демо.

Статусы: **есть** - реализация/материал найдены; **частично** - есть ограниченная проверка; **нет подтверждения** - не найден нужный результат; **ожидание** - внешняя зависимость. Наличие файла не доказывает качество.

## 1. Проверять достоверность отдельно от наличия ссылок

Единица оценки - одно **существенное утверждение**, влияющее на диагноз, сравнение, экономику, обещание или решение. Предварительно выписать такие утверждения вручную; строка Markdown с числом не является надёжным знаменателем всех утверждений.

- **Покрытие происхождением** = утверждения с открываемым источником и точным местом / все существенные утверждения. Наличие E-номера без исходника недостаточно.
- **Поддержка источником** = утверждения, смысл/масштаб которых действительно следует из цитаты/расчёта / проверенные утверждения. Для всех критичных решений сверять все основания; для остальных отдельно задавать выборку и показывать её размер. Не показывать долю выборки как качество всего проекта.
- **Корректность типа** = верно размеченные fact/hypothesis/forecast/synthetic / проверенные утверждения. Источник может содержать чужое мнение: факт «автор сказал X» не превращает X в факт рынка.
- **Точность числа** = корректные значения с правильными единицами/базами/периодами / проверенные числовые утверждения. Вычисление воспроизводится; округление задано заранее.
- **Просроченные основания** = критичные основания, не актуальные для даты решения. Цель перед сдачей - 0 известных неразобранных просроченных оснований, а не универсальный срок годности.

Предложенный внутренний стоп: **0 выдуманных критичных источников/чисел; 100% критичных оснований проверены по содержанию; 100% синтетики обозначено**. Это условия приёмки команды, не существующие результаты и не обещание абсолютной истинности. Для прочих утверждений публиковать фактический n/N, ошибки и исправления без искусственного единого «индекса доверия 93%».

## 2. Качество анализа, идеи и стратегии

Предложенная экспертная рубрика 0/1/2 на каждое измерение. 0 - отсутствует/неверно; 1 - есть, но существенно неполно; 2 - конкретно и проверяемо. Два оценщика независимо оценивают результат без знания режима, затем сохраняют расхождения и причины; не усреднять опасную ошибку хорошим стилем.

| Измерение | Для 2 баллов нужны |
|---|---|
| Постановка | Одно принимаемое решение, получатель, целевая переменная, ограничения и граница данных |
| Диагноз | Разделены симптомы и причины, есть альтернативные объяснения и способ различить их |
| Источники | Происхождение/место/период, смысловая поддержка и существенные ограничения |
| Варианты | Отличаются механизмами, включают неудобные варианты и рассматриваются по одинаковым основаниям |
| Опровержимость | Назван факт, при котором рекомендация станет неверной, и как его получить |
| Экономика | Связаны польза, затраты/доходы, ресурсы, диапазоны и чувствительность; неизвестное не заменено точным числом |
| Исполнимость | У выбранного направления есть первые шаги, владелец, ресурсы и реальные ограничения |
| Согласованность | Аудитория, продуктовые отказы и сообщения не противоречат друг другу |
| План опыта | Исходная база, сравнение, полезный эффект, срок, правило решения и guardrails |
| Ясность | Руководитель пересказывает решение, причины и риск, может найти исходный фрагмент |

Сумму можно использовать для локального сравнения версий при одной рубрике, но не называть баллом конкурса. Любая выдуманная критическая опора или неразрешённые данные останавливают приёмку независимо от суммы. Не поручать окончательную оценку той же модели, которая написала ответ.

Для выбора идей не использовать произвольный RICE при выдуманных Reach/Impact. Сначала отсечь нарушающие ограничения, затем сравнить оставшиеся по пользе, стоимости, риску, времени получения свидетельств и обратимости. Весовую матрицу утверждает руководитель; проверить, меняется ли лидер при разумном изменении весов. Если меняется - показать неустойчивость выбора.

## 3. Пользовательский опыт и работа агента

Измерять на задачах, а не только опросом «понравился ли дизайн». Стартовый предлагаемый пилот - 5 целевых пользователей для обнаружения проблем, не статистическая оценка всего рынка.

| Задача | Измерение | Предлагаемое внутреннее условие, ещё не измерено |
|---|---|---|
| Запустить проект | Время до подтверждённой постановки, ошибки, подсказки наблюдателя | Каждый участник завершает; ориентир ≤5 минут из T11, отклонения сохранять |
| Понять краткое решение | Участник своими словами называет решение, 2 основания и главный риск | Все ключевые элементы без смысловой подмены; записать n/N |
| Открыть доказательство | Время до нужной строки первоисточника, число переходов | Критичный источник находится и подтверждает смысл; локальный ориентир ≤60 с |
| Не согласиться / исправить | Вводит новую цель/ограничение, видит что изменилось | Нет тихого удаления истории и изменения выбора за человека |
| Остановить / продолжить | Состояние до/после, повторные действия, ошибки | 0 потерь подтверждённых решений; 0 незаметных повторных платных действий |
| Перенести | Проверка в другой среде и совпадение состояния | Продолжение без пересказа; секреты не в архиве |
| Найти нужное | Заранее заданные вопросы к реестру, hit@k и время | Отдельно n запросов и ошибки, без обещания семантического поиска |

Самостоятельность = действия без вмешательства / все действия **между обязательными точками выбора**. Согласования руководителя не считать дефектами автономности. Число остановок само по себе не качество: важны необходимость и время человека. Ошибки и время после повтора включать в итог, а не исключать неудачный запуск.

## 4. Экономика и сравнение

Полная стоимость результата = модель + поиск + инструменты + повторные вызовы + доработка человеком. Денежный расход неизвестен хотя бы по компоненту - показывать известную часть, долю покрытия и неизвестное, а не общий «0 ₽». Подписку учитывать согласованным способом и не смешивать предельную цену вызова с полной долей подписки.

Паспорт замера: данные, запрос, модель/версия/настройки, сервисы, start/end, активное время человека, время ожидания, доступный счётчик, валюта/дата курса, успешные и неудачные повторы, ручная помощь. Интервалы между записями журнала не равны чистому времени модели.

Сравнение: одна задача и доступные материалы, заранее заданная рубрика, одинаковый уровень модели, несколько независимых прогонов каждого режима. Практический старт - 3, а не доказательство статистической значимости; затем оценить разброс и необходимый размер опыта. Для ручного аналитика - тот же результат и условия доступа. Точность, время, цена и участие человека показывать отдельно; не прятать неуспешные прогоны в средней стоимости только успехов.

Пользовательские бизнес-метрики выбираются по реальному продукту (переход в оплату, удержание когорты, маржинальная прибыль), а показатели качества агента выше - по работе агента. Рост оценки красивого текста не равен росту бизнеса.
