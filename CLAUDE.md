# Правила командной работы (читать каждому ИИ-помощнику перед любым действием)

Над этим репозиторием одновременно работают три человека — Ратмир, Влад и Ника, у каждого свой ИИ-помощник.
Общая память команды — этот репозиторий, `TASKS.md` и канал агентов (issue #1, правила в `docs/COMMS.md`).

> **Две роли, не путай.** В корне репозитория ты — помощник разработчика команды и живёшь по этому файлу.
> Продукт, который мы сдаём, лежит в папке `strateg/`: у него свои инструкции (`strateg/AGENTS.md`).
> Ты их пишешь и проверяешь, но не исполняешь, пока человек не попросил «прогони Стратега».

## Цикл работы (строго по порядку)

1. `git pull --rebase` — всегда перед началом и перед каждым пушем.
2. Прочитай `TASKS.md` целиком и канал агентов (`docs/COMMS.md`). Возьми задачу, назначенную твоему человеку, у которой выполнены все зависимости (колонка «Зависит от»).
3. **Захват задачи — отдельным коммитом и сразу пуш:**
   - в строке задачи поменяй статус на `в работе: <Имя>-<ИИ>`;
   - `git add TASKS.md && git commit -m "claim T<номер>: <Имя>" && git push`;
   - если пуш отклонён — `git pull --rebase`, проверь, не занял ли задачу кто-то другой. Занял — откати свою правку и выбери другую.
   - Не начинай работу, пока захват не запушен.
4. Делай задачу. Трогай только файлы и папки из колонки «Где». Нужно поменять чужое — см. «Чужая зона».
5. Коммить маленькими шагами. Перед каждым пушем: `git pull --rebase`, проверка (см. «Проверка перед пушем»), чтение канала, затем `git push`.
6. Готово → в `TASKS.md` статус `готово: <Имя>-<ИИ>`, в «Заметки» одна строка: что сделано и как проверить. Коммит `done T<номер>`, пуш, сообщение в канал, если от задачи кто-то зависит.
7. Скажи человеку, что задача закрыта, и предложи следующую.

## Жёсткие запреты

- Никаких `git push --force`, `git reset --hard` на `main`, удаления чужих файлов.
- Не переписывай `CLAUDE.md` и `docs/CONTRACT.md` без согласия ведущего (Ратмир). Поменял по согласию — запись в «Журнал решений» внизу `TASKS.md`.
- Не меняй чужие строки в `TASKS.md`. Новые задачи добавляй в конец таблицы со статусом `свободна`.
- Никаких секретов и ключей в репозитории: только `.env` (он в `.gitignore`) и `.env.example` с пустыми значениями.
- Только открытые источники и собственные материалы. Никаких закрытых данных МегаФона и других компаний, никаких персональных данных.
- Новая зависимость, платный сервис или модель — только с записью в «Журнал решений»: что это, зачем, сколько стоит.
- Конфликт при rebase: сохрани изменения обеих сторон. Не понимаешь чужое — остановись и спроси человека.

## Чужая зона

Нашёл ошибку в чужой части — не правь молча. Напиши автору в канал; если правка крупная — добавь задачу «Фикс: …» в `TASKS.md`. Очевидную правку в одну-две строки можно сделать отдельным коммитом `fix(<папка>): …` и сообщить автору в канале.

## Проект

- **Что делаем:** ИИ-агент «Стратег Фабрики продуктов» для номинации «ИИ-проект» MGIMO AI Challenge (задание МегаФона). Полный текст задания и критерии — `docs/CASE.md`. Прочитай его целиком перед первой задачей.
- **Срок:** приём работ до 22 ноября 2026, 23:59 МСК. Внутренний срок готовности — 20 ноября.
- **Форма продукта:** не программа и не автономный бот, а папка `strateg/` с инструкциями, знаниями и небольшими скриптами, которую открывают в Cursor, Claude Code или Codex.
- **Главный принцип отбора:** число агентов и объём инструкций — не преимущество. Каждый компонент добавляем, только если можем показать его пользу (качество, скорость, стоимость, удобство). Не можешь назвать пользу — не добавляй.
- **Контракт между частями:** `docs/CONTRACT.md`. Формат реестра доказательств, состояния задачи и журнала — только оттуда.
- **Скрипты:** Python 3.9+, только стандартная библиотека. Запуск из папки `strateg/`.
- **Проверка перед пушем:** `python3 -m unittest discover -s strateg/tools -p "test_*.py"` (когда появятся тесты); для правок инструкций и навыков — прогон затронутого шага на пробном проекте.
